# TORQ GARAGE — Design System Reference

Читать перед добавлением новых страниц/компонентов.

## Токены

Цвета, шрифты — только через CSS-переменные из `app/globals.css`. Хардкод hex запрещён.
Один акцент: `--color-signal` (#ff4713). Второй акцентный цвет не добавлять.

## Button.tsx

Все интерактивные CTA идут через `components/Button.tsx`. Не дублировать разметку кнопки вручную.

```tsx
<Button href="/contacts" icon>Записаться</Button>          // primary, на любом фоне
<Button href="/parts" variant="ghost" icon>Каталог</Button> // вторичная, тёмный фон
<Button variant="ghost-dark">Подробнее</Button>              // вторичная, светлый (cream) фон
<Button type="submit" fullWidth>Отправить</Button>           // форма
```

Variants:
- `primary` — сигнальный оранжевый, для главного действия на странице (запись, отправка формы). Один primary-CTA на экран/секцию, не больше.
- `ghost` — контурная, для тёмных секций (asphalt/surface).
- `ghost-dark` — контурная, для светлых (cream) секций. Использовать на страницах услуг вне hero-секций.

Sizes: `sm` (внутри Header/компактные места), `md` (по умолчанию), `lg` (CtaBand, финальные секции).

## card-depth — когда обязателен

Правило: `card-depth` применяется к элементам, которые представляют **самостоятельную кликабельную/интерактивную единицу с собственным содержимым** — то, что пользователь мысленно "берёт в руки": карточка услуги, карточка кейса, форма, карточка товара, блок гарантии.

**Обязательно:**
- Карточки услуг/кейсов/товаров (Services, Cases, PartsTeaser)
- Формы (LeadForm)
- Карточки гарантий/преимуществ (Guarantees)
- Любой самостоятельный контентный блок на cream/asphalt фоне, который логически "плитка"

**Не применять:**
- К самим кнопкам (у кнопок свои hover-состояния, не hairline-глубина)
- К строкам таблиц (каталог запчастей — табличная строка, не карточка)
- К навигационным элементам (Header, Footer-ссылки)
- К инлайн-бейджам/лейблам (mono-подписи вроде `FORM-01`, `SHEET-01`)
- К секциям целиком (секция — не карточка, у неё нет "приподнятости")

Логика: `card-depth` сигнализирует "это отдельный объект с весом", поэтому неограниченное применение (на всём подряд) обесценивает эффект — как только всё "приподнято", ничего не выглядит приподнятым.

## Разметка страниц услуг (СТО/Тюнинг/Детейлинг/Запчасти)

Единая структура для новых 8 страниц:
1. Hero страницы (тёмный, asphalt) — H1 с интентом страницы, короткий подзаголовок, один primary CTA
2. Блок услуг/прайса этого направления (карточки с `card-depth`)
3. Процесс/этапы (если применимо)
4. Trust-блок (гарантии/сертификаты специфичные для направления)
5. FAQ (для SEO — вопросы с интентом "сколько стоит", "сколько занимает")
6. CtaBand в конце (как на главной)

H1 и мета-теги каждой страницы должны быть построены на отдельном интенте (не дублировать формулировки между СТО/Тюнинг, чтобы не каннибализировать друг друга в поиске).

## SEO-каркас (уже готово, не пересобирать)

- `lib/site.ts` — единая точка правды: URL, данные бизнеса, список роутов для sitemap
- `app/sitemap.ts` / `app/robots.ts` — автогенерация, при добавлении страницы дописать путь в `SITE_ROUTES`
- `components/BusinessSchema.tsx` — JSON-LD AutoRepair, рендерится один раз в layout, трогать не нужно
- На каждой новой странице услуг — свой `export const metadata` с уникальными title/description под интент страницы (пример ниже)
- `/og-image.jpg` — плейсхолдер-путь в metadata, реального файла в `public/` ещё нет — добавить 1200×630 при заполнении портфолио

```tsx
// app/tuning/page.tsx
export const metadata: Metadata = {
  title: "Тюнинг и чип-тюнинг авто в Днепре",
  description: "Прошивка ЭБУ на дино-стенде, механические доработки, обвесы...",
  alternates: { canonical: "/tuning" },
};
```

## Мультиязычность (RU/UK)

Паттерн как на biotek.ua: RU — дефолтная локаль без префикса (`/`, `/tuning`), UK — на `/uk/*` (`/uk`, `/uk/tuning`). Реализовано через `next-intl`.

При добавлении новой страницы:
1. Создать `app/[locale]/<page>/page.tsx`
2. Добавить ключи текста в **оба** `messages/ru.json` и `messages/uk.json` — не оставлять страницу непереведённой
3. Использовать `useTranslations("<namespace>")` в компонентах, `Link`/`useRouter` только из `@/i18n/navigation` (не из `next/link`/`next/navigation`)
4. Добавить путь в `SITE_ROUTES` (`lib/site.ts`) — sitemap подхватит обе локали автоматически
5. `generateMetadata` на странице — с `getTranslations({ locale, namespace: "meta" })` по аналогии с корневым layout
